# 移动平台角色参数配置与QGC检查

本次增量日期：2026年10月27日。

适用工程为`moving-base`分支，修改前提交为`897f6768719afbe827f2cd7c4276cec4426c3397`，基础版本为`v1.18.0-rc1`。本增量仅增加参数定义、按角色标记使用中的参数，以及使用说明。没有修改消息结构、车载导航、机载对准、解锁检查或控制器，没有修改QGC。

## 1. 本次实现边界

本次完成配置入口，不包含车载参考发送流、机载接收或对准算法。`MB_REF_RATE`等数值在当前增量中可以配置保存，但尚未接入对应的数据处理功能。选择角色不表示该角色的业务功能已经完成，也不会由本增量自动建立参考发送流；自动发送将在发送流增量中接入这些参数。TIMESYNC现有实现及已有消息流不因本增量自动调整。

后续发送功能使用同一套参数，不再另建独立采集任务。移植时参考1021版的角色设计，并修正唯一通信实例约束、主EKF切换时的新旧数据混用等已列出的复审问题，不直接应用1021版全部补丁。

## 2. 参数约定

所有本功能新增参数均以`MB_`开头，当前名称均不超过16个字符，修改后均要求重启。

| 参数 | 默认值 | 取值/单位 | 使用角色 | 说明 |
|---|---:|---|---|---|
| `MB_ROLE` | 0 | 0关闭、1车载、2机载 | 始终 | 设备功能角色；不替代解锁检查 |
| `MB_MAV_INST` | 2 | 0、1、2 | 车载、机载 | 对应`MAV_0_*`、`MAV_1_*`、`MAV_2_*`参数配置实例，不是运行编号 |
| `MB_TS_RATE` | 10 | 1～20 Hz | 车载、机载 | TIMESYNC主动请求目标频率，不表示同步已收敛 |
| `MB_REF_RATE` | 50 | 1～100 Hz | 车载 | 参考快照采集与发送目标频率，不改变IMU或EKF计算频率 |
| `MB_SRC_SYS` | 1 | 1～255 | 机载 | 可信车载端`MAV_SYS_ID`，不使用0作为任意来源通配值 |
| `MB_SRC_COMP` | 1 | 1～255 | 机载 | 可信车载端`MAV_COMP_ID` |
| `MB_REF_TMO` | 200 | 20～5000 ms | 机载 | 合格参考接收超时，不代替样本龄期或同步映射时效检查 |

默认值是初始配置，不是已完成实车验证的指标。例如实际车载系统编号为43时，机载端应把`MB_SRC_SYS`设为43，而不是沿用默认1。

### 按角色显示的预期结果

正常启动时，`rc.mb_params`通过`param compare`读取角色，使用`param touch`标记相应参数。它不修改任何参数值，不启动MAVLink实例或算法任务。常规MAVLink参数列表只遍历已使用的参数，因此无需QGC二次开发。

| 保存角色并重启 | 本功能正常应提供的参数 |
|---|---|
| 关闭：0 | `MB_ROLE` |
| 车载：1 | `MB_ROLE`、`MB_MAV_INST`、`MB_TS_RATE`、`MB_REF_RATE` |
| 机载：2 | `MB_ROLE`、`MB_MAV_INST`、`MB_TS_RATE`、`MB_SRC_SYS`、`MB_SRC_COMP`、`MB_REF_TMO` |

这是重启后按需提供参数，不是立即弹出对话框，也不是权限隔离。QGC缓存、直接请求某个参数，或其他代码读取该参数，都可能使额外参数出现在本次连接中；不能把参数是否隐藏作为功能是否启用的依据。后续业务代码仍须按角色及专用实例检查。

同一次启动中，使用标记只增加、不主动清除。切换角色后须保存、重启、重新连接并刷新参数列表；不要仅在当前连接中切换角色就判断显示效果。脚本不会清除另一角色已保存的数值。

## 3. QGC检查步骤

1. 在虚拟机编译本增量，备份实物参数后烧录。全程拆桨、不解锁，不清空全部参数，不更换bootloader。
2. 飞控USB连接QGC，在参数页重新读取参数后搜索`MB_`。默认角色应为0；若先前已保存过同名参数，以保存值为准。
3. 将`MB_ROLE`设为1，保存并重启。重新连接后搜索`MB_`，核对车载四项，分组为“移动平台公共”和“移动平台车载”。
4. 记录`MB_REF_RATE`当前数值，将`MB_ROLE`设为2，保存并重启；重新加载后核对机载六项，分组为“移动平台公共”和“移动平台机载”。
5. 将`MB_ROLE`改回1并重启，确认车载配置值仍保留；最后按本次实物用途选择角色，避免留在错误角色。

若QGC一直显示旧列表，先断开、重新连接并刷新参数。描述未更新时检查实际固件版本及元数据读取，不采用重置全部参数解决。若需精确区分参数是否被标记为使用，可用控制台的`x`标志核对。

### 控制台复核

```sh
param show MB_*
```

这是查看当前已使用参数的主要方式。查看所有定义可执行：

```sh
param show -a
```

注意当前基线的`-a`会列出全部参数，不保证后面的过滤表达式仍生效。正常角色0只应把`MB_ROLE`标为使用，其他MB参数虽已编译存在，但不应由本脚本主动标记。

车载角色设置示例（逐条执行）：

```sh
param set MB_ROLE 1
param save
reboot
```

重启后再配置可见的车载项目，不以查询所有参数或手动`param touch`代替自动显示验收。

## 4. 专用串口配置仍复用原参数

`MB_MAV_INST=2`表示以后由`MAV_2_*`配置指定车机链路，物理端口由`MAV_2_CONFIG`选择。7-Nano V2应按实物引出的TELEM1、TELEM2选择，不把软件中的TELEM3直接当作实物插座。

| 已有参数 | 当前台架建议 | 备注 |
|---|---|---|
| `MAV_2_CONFIG` | TELEM2（102） | 先排除TFmini等其他功能占用 |
| `MAV_2_MODE` | Custom（1） | 为后续只启动参考及同步流准备；当前会停止Onboard默认姿态等消息流 |
| `MAV_2_RATE` | 0 | 自动带宽；不是禁止发送，也不是无限带宽 |
| `MAV_2_FLOW_CTRL` | 0 | TX/RX/GND三线连接时关闭流控 |
| `SER_TEL2_BAUD` | 115200 | 双方一致；频率提高后按实际负载重新验收 |

本增量不会自动修改这张表中的已有参数。普通串口参数仍使用原名称，不增加重复的`MB_PORT`或`MB_BAUD`别名。USB/QGC链路保持独立。

不要在不了解实物用途时批量关闭传感器。本项目既往台架配置曾为`SENS_TFMINI_CFG=102`，导致TELEM2冲突；仅在确认不使用TFmini时把它设为0并重启。此项不由角色脚本自动改写。

在本参数增量阶段，如仍需手动测试TIMESYNC，可在Custom串口实例成功启动后执行：

```sh
mavlink stream -d /dev/ttyS3 -s HEARTBEAT -r 1
mavlink stream -d /dev/ttyS3 -s TIMESYNC -r 10
mavlink status
mavlink status streams
```

上述命令的10 Hz是临时手动流配置，当前不由`MB_TS_RATE`联动控制，重启后需重新设置。电脑程序应答后再检查该串口接收来源和`timesync_status`，不要把USB的同步状态误当成车机串口结果。
