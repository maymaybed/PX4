# 车载参考航向、角色隔离与双板兼容

本增量只修改车载角色的参考发布路径。参考协议、速度有效位、TIMESYNC 门限、机载 EKF 与解锁检查保持原定义。

## 地面磁航向

车载端不再把飞行中磁对齐完成作为唯一的航向有效入口。
在既有姿态有效、样本时效及估计器实例检查通过后，仍要求航向已对齐且无航向融合故障。
原有 `heading_good_for_control` 合格路径继续保留；地面磁航向则额外要求：

- 正在使用磁航向或三轴磁融合。
- 磁航向与滤波器一致。
- 没有磁场扰动、磁传感器故障或磁融合数值故障。

不会修改 EKF 的 `mag_aligned_in_flight` 或 `heading_good_for_control`，也不会将这些车载参考位当作机载起飞许可。
无 GPS 时，磁航向可以按上述质量有效；水平、垂直速度仍按原有速度质量门控判断，不因“静止”直接置为有效。
台架先前有效位为17；在同样倾斜/角速度质量和合格磁航向下，修复后应为19，需刷入新固件再实测确认。

## 角色和串口边界

角色参数沿用保存后重启生效的约定。

| 角色 | 行为 |
| --- | --- |
| `MB_ROLE=0` | 不给串口附加车载配置标记，不启动参考流，不创建车载订阅或发布者；原 MAVLink 流按原配置启动 |
| `MB_ROLE=1` | 仅选定的 MAV 配置实例、Custom 模式和 `/dev/ttyS*` 串口允许车载采集与推流 |
| `MB_ROLE=2` | 当前增量不启动车载发送；机载接收与对齐属于后续增量 |

普通 USB、UDP、其他串口实例不能通过手动请求绕过参考流工厂的角色/链路检查。
普通链路先按配置标记快速退出；只有候选专用链路才查询车载参数，uORB 订阅和发布对象仅在工厂确认角色1后创建。
活动流只读缓存的车载启用状态与 IMU 模式；角色/实例变更由既有参数更新路径刷新，关闭后停止参考发布并释放唯一发布者所有权。
专用流的完整启动配置仍需按参数说明重启生效，串口沿用当前 `MAV_x_*` 和 `SER_TELx_BAUD` 设置。

最终样本龄期按采集完成后的发布时刻统一检查，保持原有100 ms数据和2 s质量门限。

## 兼容板级目标

| 飞控 | 构建目标 | TELEM2 |
| --- | --- | --- |
| CUAV 7-Nano V2 | `make cuav_7-nano_default` | `/dev/ttyS3` |
| CUAV V5 Nano / FMUv5 | `make px4_fmu-v5_moving-base` | `/dev/ttyS2` |

V5 Nano 的官方基础构建目标为 FMUv5，见 [PX4 构建说明](https://github.com/PX4/PX4-Autopilot/blob/main/docs/en/dev_setup/building_px4.md)。
新增 `moving-base` 板级标签继承 FMUv5 默认配置，仅切换私有方言；原 `px4_fmu-v5_default` 配置不改动。
两种板复用同一套代码、协议和 MB 参数，分别生成各自固件，不能互刷。
实际串口通过 `MAV_x_CONFIG` 配置，应用逻辑没有把专用串口固定为某个 ttyS 编号。

本轮两款目标均编译通过；V5 当前完整配置 Flash 约99%，后续新增功能需重新评估容量。
本轮没有连接 V5 Nano 实板，不能将编译结论写成其台架验收。

## 验证与实板复测

测试程序与构建产物保存在仓库外的 `../moving_platform_test` 和 `../moving_platform_env`。

- 真实启动片段与功能加入前版本比较：432组角色关闭启动参数一致，54组角色/实例/模式选择检查通过。
- 直接编译生产发送流的接口替身测试：覆盖无GPS磁航向、故障门控、单/多EKF、实例切换、采集抢占后超时、缓存句柄、角色关闭及所有权释放。
- 含私有方言和车载流的实际SITL：角色0时保持心跳/姿态/位置遥测，车载主题从未发布，手动参考流请求被服务端拒绝。
- 7-Nano 与 FMUv5 分别在独立目录构建；NuttX 源树内会留下板级对象，两种目标使用独立源码副本，避免旧对象混入。

实板刷入后先验证 `MB_ROLE=0` 的普通功能，再配置角色1与指定串口，检查无GPS地面磁航向和参考有效位。
不要为制造航向有效位而伪造飞行状态；磁质量失效时仍应清除航向有效位。

## 本机配置与开销控制（2026-10-30）

`Mavlink::moving_base_transmitter_enabled()` 是配置、流创建、大小计算与发送共用的车载判据。
角色、实例与 IMU 模式在启动和既有参数更新通知中刷新；发送热路径不调用 param_find 或 param_get。
参数更新订阅沿用现有 1 s 间隔，关闭角色通常约 1 s 生效，不承诺逐帧立即关闭。
不新增周期任务，不修改参考流、TIMESYNC 或调度频率，也不增加运行期配置扫描。

启动脚本仅在车载角色检查所选实例是否禁用、是否为 Custom；错误输出一次提示，不自动修改参数。
少量 MB 参数可以长期存在，参数可见或被 touch 不代表功能启用。
固件特性是否包含、设备间波特率与接线由使用者核查，不增加专门校验或告警。
